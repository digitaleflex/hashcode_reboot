# HASHCODE REBOOT
## Production-ready onboarding & community entry platform

Tu es maintenant le Lead Product Engineer, Senior UX/UI Designer,
Growth Engineer, Product Strategist et QA Engineer responsable de
concevoir et développer HASHCODE REBOOT.

Tu dois travailler comme si tu étais responsable de livrer une
application réelle destinée à être mise en production aujourd'hui.

NE TE CONTENTE PAS DE PRODUIRE UNE MAQUETTE.

Tu dois :
1. analyser le projet existant ;
2. comprendre l'architecture actuelle ;
3. proposer les corrections nécessaires ;
4. concevoir l'expérience utilisateur ;

==================================================
# 1. CONTEXTE DU PRODUIT
==================================================

HASHCODE est une communauté technologique en phase de
repositionnement et de relance.

HASHCODE revient autour de trois grands axes :

- Web Development
- Cybersecurity
- Applied AI

L'objectif n'est plus simplement de partager des tutoriels.

HASHCODE veut permettre aux membres de :

- apprendre ;
- pratiquer ;
- construire ;
- expérimenter ;
- collaborer ;
- progresser.

Le nouveau HASHCODE Registry sera à terme le centre de gestion
des profils, parcours, missions et progression des membres.

Mais le Registry complet n'est PAS encore nécessaire pour cette phase.

Nous construisons maintenant :

HASHCODE REBOOT

URL cible :

https://reboot.joinhashcode.com

Cette plateforme constitue le nouveau point d'entrée de la communauté.

==================================================
# 2. OBJECTIF PRINCIPAL
==================================================

Construire une expérience de profilage extrêmement fluide permettant
de comprendre rapidement un nouveau membre sans lui donner
l'impression de remplir un long formulaire.

Objectifs :

- moins de 3 minutes maximum ;
- cible idéale : 60 à 120 secondes ;
- très faible friction ;
- majorité des réponses par clic ;
- questions conditionnelles ;
- collecte intelligente ;
- profil généré à la fin ;
- segmentation exploitable ;
- possibilité de rejoindre la communauté officielle WhatsApp
  après validation du parcours.

PRINCIPE UX CENTRAL :

"Tu ne remplis pas un formulaire.
Tu construis ton profil HASHCODE."

# 16. DONNÉES À COLLECTER
==================================================

Les données doivent être réparties en trois catégories.

------------------------------------------
IDENTITÉ
------------------------------------------

- prénom ;
- nom ;
- email ;
- WhatsApp ;
- pays ;
- ville/région facultative ;
- genre facultatif.

Le genre ne doit jamais être obligatoire.

Options :

- Homme
- Femme
- Autre
- Préfère ne pas répondre

------------------------------------------
PROFIL
------------------------------------------

- domaine principal ;
- domaines secondaires ;
- niveau ;
- technologies / compétences ;
- expérience.

------------------------------------------
OBJECTIFS
------------------------------------------

- objectif principal ;
- objectif secondaire ;
- objectif à 3 mois ;
- type de projet ;
- situation professionnelle si pertinente.

------------------------------------------
DISPONIBILITÉ
------------------------------------------

- temps disponible par semaine ;
- moments disponibles ;
- préférence de rythme.

------------------------------------------
APPRENTISSAGE
------------------------------------------

- apprendre seul ;
- parcours structuré ;
- groupe ;
- projet ;
- mentor.

------------------------------------------
MENTORAT
------------------------------------------

Conditionnel uniquement.

Demander :

"As-tu besoin d'un accompagnement personnalisé ?"

Options :

- Non
- Peut-être
- Oui

Si Non :

ne poser aucune question supplémentaire de mentorat.

Si Peut-être :

demander ce qui pourrait le convaincre.

Si Oui :

demander :

- type de mentorat ;
- fréquence souhaitée ;
- domaine du mentorat.

------------------------------------------
DISPOSITION À INVESTIR
------------------------------------------

Uniquement si l'utilisateur manifeste un intérêt pour
l'accompagnement.

Question :

"Si HASHCODE proposait un accompagnement personnalisé adapté
à tes objectifs, serais-tu prêt à investir dans ton accompagnement ?"

Options :

- Oui
- Peut-être
- Pas pour le moment

Si Oui ou Peut-être :

demander une fourchette :

- Moins de 2 500 FCFA / mois
- 2 500 – 5 000 FCFA / mois
- 5 000 – 10 000 FCFA / mois
- 10 000 – 20 000 FCFA / mois
- 20 000 – 30 000 FCFA / mois
- Plus de 30 000 FCFA / mois
- Je ne sais pas encore

NE PAS demander un montant libre.

IMPORTANT :

Présenter cette question comme une recherche de besoins,
pas comme une vente.

# 18. LOGIQUE CONDITIONNELLE
==================================================

Construire un vrai moteur de conditions.

Exemples :

IF domain = cybersecurity
→ proposer des sous-domaines cyber.

IF domain = web
→ proposer des spécialisations web.

IF domain = ai
→ proposer des spécialisations AI.

IF mentoring = no
→ ne pas demander budget.

IF mentoring = maybe
→ questions légères.

IF mentoring = yes
→ type de mentorat + fréquence + budget.

IF goal = project
→ demander si le projet existe déjà.

IF goal = employment
→ demander situation actuelle si pertinent.

IF goal = entrepreneurship
→ demander stade du projet.

IF availability < 2h
→ proposer un rythme léger.

IF availability >= 10h
→ possibilité de proposer parcours plus intensif.

Le moteur doit être extensible.

NE PAS coder toutes les conditions en dur dans des composants
UI chaotiques.

Créer une structure de configuration propre.

Par exemple :

questions/
profiling/
rules/

ou une architecture équivalente adaptée au projet.
